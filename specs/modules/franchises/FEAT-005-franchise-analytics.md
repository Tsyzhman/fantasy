# FEAT-005: Аналитика франшиз {#root}

## Простыми словами {#plain-language}
«Франшизы» — самостоятельный раздел Fantasy: пользователь выбирает чемпионаты и номера туров, видит стиль выбора игроков, капитанов и покупок, заморозки и xФО. Все расчёты выполняет код. Модели ИИ не нужны.

## Цель и границы {#scope}
Сезон решений — 2026/27; история футболистов для формы — вся доступная до каждого тура. Начальный список H2H: 503,19,65,5,18,433,223,40,401,27,25,23. Повтор ID исключён. Стартовые составы не считаются трансферами. ALT/ФО/FFO не изменяются. Источник формулы xФО — пользовательский `резы2.xlsx`, лист «Лист1», G/N/P.

## Результат функции {#goal}
Пользователь самостоятельно сравнивает решения франшиз на выбранной дистанции. Смена фильтра не запускает сбор H2H или обращение к ИИ. Показатели объясняют стиль выбора и качество моментов, не объявляют менеджеров сильнее по одному индексу.

## Участники {#actors}
- Авторизованный пользователь любой франшизы: чтение, фильтрация, переход к профилю, локальный CSV.
- Оператор: запуск коллектора, миграция и включение расписания обновлений.
- Анонимный посетитель: вход через общую авторизацию, данные API недоступны.

## Сценарии {#scenarios}
1. Открыть «Франшизы», выбрать чемпионаты и включительный диапазон туров, получить пересчитанные рейтинги и знаменатели.
2. Выбрать название франшизы на графике, в таблице или списке; посмотреть менеджеров, прогнозы, форму и гипотезы.
3. Открыть xФО: сравнить полные XI и их фактические очки, проверить покрытие лиг и замены отсутствующих компонентов нулями по Excel.
4. Открыть заморозки: увидеть частоту, завершённые эффекты, замороженных/выпущенных и исходную доску.
5. Выбрать пустую дистанцию: явное отсутствие составов, без возврата к данным всего сезона.

## Контракты {#contracts}
Рейтинги и все знаменатели применяют одни фильтры лиг/туров. Франшиза в UI выбирает профиль внутри общей сопоставимой выборки. Состояние фильтров сохраняется в URL. Для старых решений запрещено использовать будущие матчи и текущий пересчёт прогнозов. Служебный сбор недоступен через публичный GET. Готовый снимок публикуется целиком после сохранения исходных H2H-записей; сбой не заменяет рабочий снимок неполным результатом.

Диапазон номеров туров применяется независимо к каждой лиге по нумерации H2H: 1–2 включает туры 1 и 2 каждого выбранного чемпионата независимо от дат. Неполное покрытие xФО не исключает лигу или её составы из остальных расчётов.

## Управляющие документы {#governing-specs}
Существующий продуктовый канон: `specs/common/main.md`; архитектура и доступ: `specs/common/structure.md`, session auth. Доступ к аналитике одинаков для пользователей разных франшиз.

## Сценарии и UI {#ui}
`/franchises` доступен из общей навигации рядом с другими модулями. Фильтры: чемпионаты, включительный диапазон номеров туров, франшиза. Общий обзор, профиль франшизы, менеджеры, xФО, заморозки. Названия франшиз подписаны рядом с точками; числовые ID остаются только внутренними ключами. Таблицы сортируются, единицы и знаменатели раскрыты. Светлая/тёмная темы и мобильный вид. Пустой диапазон не подменяется всем сезоном. Ссылка сохраняет выбранный диапазон.

Под фильтрами поясняется независимая нумерация туров. Список «Какие чемпионаты вошли в расчёт» показывает число составов каждой выбранной лиги для текущей франшизы или всех франшиз; пустые лиги сохраняются с явным нулевым покрытием. Таблица xФО по чемпионатам объясняет отсутствие полного XI, не скрывая лигу.

## Математика стиля {#style}
Владение XI — среднее H2H-владения 11 игроков. Ориентир общего поля взвешен владением и позициями, относится к ростеру 15 игроков. Капитанский ориентир: sum(cap²)/sum(cap). Ориентир покупок — положительный прирост H2H-владения, не полный журнал трансферов. Форма — средние серверные очки последних 5 выходов (минимум 3), рост формы — последние 3 против предыдущих 3–7 с порогом +2. Усреднение: сначала состав/тур, затем лига, затем равный вес выбранных лиг. Рейтинг редкости: 40% ранг владения относительно сравниваемых франшиз +30% редкость капитана +30% низкий прирост владения покупок. Он не оценивает мастерство. Отсутствующие значения не равны нулю.

## Прогнозы и время {#time}
Для решения используются только матчи до начала тура (консервативно kickoff+3h) и снимки, сохранённые до kickoff. Текущий пересчёт сервера подписан отдельно и не объясняет прошлые решения. Гипотезы причин расхождений не используют бюджет и не выдаются за причинные доказательства.

## xФО {#xfo}
Это ретроспективная оценка сыгранного матча: xG×стоимость гола +3×xA +очки времени +карточки +возвраты/сейвы +ожидаемые очки обороны +явная поправка за спарку. Стоимость гола GK/DEF=6, MID=5,FWD=4. Очки времени: выход +1, >=60 минут +1, >=90 минут MID/FWD +1. Карточки: −YC−3×RC; GK saves//3, остальные recoveries//3. Поправка за спарку по умолчанию 0, для двойного тура считаются отдельные матчи, не повторный бонус.

При >=60 минут оборонный компонент строго по формуле Excel: GK/DEF =4P(0;λ)−P(2;λ)−P(3;λ)−2P(4;λ), MID=P(0;λ), FWD=0. λ — xG соперника за матч; хвост 5+ в исходной формуле не включён и не исправляется молча. Как в IFERROR исходного Excel: пустой xG/xA/сейвы/возвраты допускается заполнить нулём только при известных минутах и xG соперника (есть подробная статистика матча). Число оценок с такой подстановкой показано отдельно. xGA не подменять нулём; матч без подробной статистики исключать. При достоверном невыходе — xФО=0; неизвестный статус — нет оценки. Сохранённые результаты Excel не являются каноном при расхождении с формулой.

Рейтинг: средний полный xФО XI за завершённый тур с удвоением капитана. Включать только полностью покрытый состав с известным фактическим результатом H2H для честного сравнения на тех же наблюдениях, показывать количество/долю покрытых составов и недоступные лиги. Частичный xФО можно показать только явно как частичный. Фактические очки для сравнения берутся из H2H и сравниваются на тех же наблюдениях. H2H уже отдаёт фактические очки капитана с удвоением: повторно умножать их нельзя. Сравнивается выбранный XI, а не официальный итог после автозамен. Факт−xФО — реализация выше/ниже оценки по моментам, не доказательство везения. Результаты после тура не используются в оценке формы до покупки.

## Заморозки {#freezes}
Явный exchange в таблице франшизы, замена последними k действующими игроками на доске. Проверка по отдельной доске обязательна. Успех: сумма очков выпущенных больше суммы замороженных. Текущие/непроверенные эпизоды не входят в итоговую успешность. Диапазон фильтрует и числитель, и знаменатель частоты.

## Данные и обновление {#data}
Повторно используемый Python-сборщик читает публичный H2H и БД, не использует LLM. Подготовка тяжёлых признаков выполняется пакетно, браузер получает агрегаты. Составы, пулы владения и доски сохраняются в `franchise_h2h_squads`, `franchise_h2h_rounds`, `franchise_h2h_states`. Готовый снимок хранится в PostgreSQL в `franchise_analytics_snapshots`; файловый источник допускается только через явную настройку для локального анализа. Версионированный компактный снимок содержит показатели составов по турам, покрытие, события замен и ссылки на источники. Публикация снимка атомарна; ошибка сохраняет предыдущий валидный снимок. Завершённые составы и пулы восстанавливаются из БД при отсутствии локального кэша. CLI `franchises:sync` выполняет весь цикл; готовый systemd-таймер обновляет данные раз в 3 часа после отдельного включения оператором. Дата сбора видна. Ключи составов/игроков/туров уникальны. HTTP-кэш ограничен сроком, текущие туры обновляются. Память ограничена одним актуальным снимком и одним процессом сбора; запрос посетителя не запускает полный парсинг сайта.

## API и ошибки {#api}
GET `/api/franchises` валидирует сезон, лиги и диапазон, возвращает агрегаты выбранной дистанции. Нет снимка: явное состояние «данные ещё не собраны». Некорректный диапазон: 400. Доступ к служебному обновлению ограничен оператором/cron. Внешние адреса формируются только из проверенных H2H путей; секреты и сырые серверные payload не передаются браузеру.

## Проверки и трассировка {#acceptance}
Проверяются формула Excel и её крайние случаи, временная отсечка, усреднение, отсутствие будущей формы, повторов, фильтры и заморозки; xФО без полных данных не ранжируется. `@spec` на collector, xФО, агрегаторе, API и UI. Интеграционная проверка на реальных данных и визуальная проверка тем/размеров.

## Ошибки и восстановление {#errors}
Неавторизованный API-запрос получает 401; неверные номера туров/лига/сезон — 400; отсутствующий или повреждённый снимок — 503 с понятным сообщением. Неизвестные компоненты не скрываются искусственным нулём за пределами явного правила Excel. Сбой парсинга или нарушение уникальности/временной отсечки прерывает обновление. Оператор проверяет завершение процесса перед снятием оставшегося после аварии lock.

## Точки ответственности {#traceability}
- `src/app/franchises/`, `src/app/api/franchises/`: защищённый экран и API.
- `src/franchises/analytics.ts`: фильтры, агрегация, рейтинги и гипотезы; контрактные проверки в `src/franchises/analytics.test.ts`.
- `src/server/franchises/snapshot.ts`: валидация и единственный кэш снимка.
- `scripts/franchise-analytics/`: сбор H2H, признаки до тура, xФО; `scripts/franchise-analytics/test_xfo.py` и workbook-fixture.
- `scripts/import-franchise-data.ts`, Prisma migration и `ops/franchises-sync.sh`: сохранение/восстановление, атомарная публикация и служебное обновление.
