# Восстановление обновления составов — 23 октября 2026

Общий сбой исправлен на сервере. Работает 0.3.145, commit `32fcc3d109cac657f48f7834c892abd04e42c4ae`. Полное покрытие всех команд не заявляется: 227 составов проверены, 35 случаев явно сохранены без записи из-за отсутствующих или противоречивых исходных данных.

## Причины и изменения

1. **Импорт SorareInside падал целиком.** Четыре обычных окна календаря были корректны, но вспомогательный ответ `scheduledLineups` содержал два матча и четыре записи клубов без страны. Парсер выбрасывал `SorareInside: invalid object` до обработки любой команды. Теперь страна восстанавливается только из полных данных того же цикла при совпадении UUID, названия, slug и типа клуба. Неизвестные или противоречивые данные по-прежнему блокируют небезопасную запись.
2. **Обычное обновление клубов стирало происхождение XI.** `upsertSeasonTeams` заменял JSON метаданных значениями логотипа и короткого названия. Вместе с ним исчезало поле `probableLineup`, используемое защитой будущего прогноза. Теперь PostgreSQL атомарно объединяет метаданные текущей строки; обычный импорт не заменяет `probableLineup`. Проверено тестом БД и двумя реальными вызовами метода внутри полностью откатанной транзакции.
3. **Деплой накапливал дубли конфигурации.** Веб содержал 314 записей окружения при 86 уникальных ключах, worker — 469 при 89. Повторные CLI overrides наследовались следующим выпуском. Теперь наследуемые значения нормализуются, а ключи, задаваемые ролью контейнера, исключаются из наследования. После выпуска: 86/86 и 89/89, дублей нет.
4. **Обязательный аудит отклонил старую зависимость.** Next.js 16.3.8 попал под опубликованные критические advisories. Версия обновлена до 16.4.2 вместе с ESLint-конфигурацией. Lockfile дополнен Linux peer-зависимостями через чистое разрешение на Linux; установка и полный CI проходят. Аудит production-зависимостей показывает ноль известных уязвимостей. [Официальное уведомление Next.js](https://nextjs.org/blog/nextjs-security-update-october-14-2026).

## Выпуск и проверка

Полный [Check](https://github.com/Tsyzhman/fantasy/actions/runs/39939922888) прошёл 1 332 модульных и 32 теста БД, аудит, проверку миграций, lint, типы, сборку и тесты непрерывного выпуска. Все десять прежних идентификаторов серверных действий присутствуют в настоящем образе.

[Сборка выпуска](https://github.com/Tsyzhman/fantasy/actions/runs/39939918757) подготовила неизменяемый артефакт, но передача образа 862 МБ из runner шла со скоростью десятков КБ/с. Workflow отменён на передаче до старта promoter. Тот же артефакт получен с проверкой GitHub SHA-256, доставлен через локальное SSH-соединение и выпущен точным committed `scripts/deploy-production-docker.sh`. Контрольные суммы, ancestry, commit/tree и image identities проверены; promoter завершился с кодом 0. Образ на production не собирался.

Сначала работали обе веб-версии, затем Caddy переключён с 3000 на 3001 с дренированием прежней версии. Его PID остался 754. Public health, веб, worker и манифест текущего выпуска совпадают. 67 наблюдений при выпуске и 600 во время подготовки — без ошибок; прежний CSS доступен с неизменным SHA-256.

Дублей цен/строк пула, orphan-строк и неуспешных миграций нет. Один scheduler worker, ноль OOM и рестартов. Сохраняются два выпуска и не более трёх READY-ревизий на scope. Финальный снимок памяти: веб около 145 MiB, worker 1.72 GiB. Это короткая проверка, а не доказательство отсутствия утечки на длительном интервале.

Временных файлов доставки и контейнеров на сервере нет. Локально удалено 1 769 324 901 байт артефактов; ссылка на общие зависимости не обходилась, её целевой каталог сохранён. [Контроль ресурсов](production-final.json), [квитанция выпуска](release-receipt.json), [очистка](cleanup.json).
