## Выпуск, миграции и сохранение пользователей

Production продолжал обслуживать запросы во время backup, restore/apply rehearsal, подготовки образов и миграций. Выпуски идут только через `scripts/deploy-production-docker.sh`: кандидат на альтернативном loopback-порту, проверка commit/health, graceful Caddy reload и drain старого web. Старый образ сохраняется для отката. Приложение не останавливалось для сборки; `compose down`, stop-and-recreate production и Caddy restart не использовались.

Перед 0.3.134 проверена копия `pre-20261010T122845Z-v0.3.134-377e362-migration.dump`, SHA256 `78fe51c512752e86c6fd5bb99290bd72b7ec24e198487bd12d1d996625eee67d`; восстановлена отдельная БД, применены миграции, копия БД удалена защищённым оператором. Новые поля/индексы совместимы со старой версией. Применено 61 миграция, незавершённых 0; пять retention индексов valid/ready.

Первое применение одного concurrent index превысило lock timeout. Его invalid index удалён только после сверки точного определения, запись миграции помечена rolled back и повтор успешно применён. В успешном первом релизе все пять индексов успели даже в прежние 5 секунд. Исправленный классификатор разрешает 30 секунд только для набора checksum-reviewed одиночных `CREATE INDEX CONCURRENTLY`; обычный/mixed DDL сохраняет 5 секунд и общий statement timeout 120 секунд. [Свидетельство восстановления](index-recovery.txt). Неудачные и отменённые CI-выпуски не выдаются за успешные.

Проверка draft на обновлении/откате использует добавленное хранилище начиная с 0.3.132. Она не означает, что исходная 0.3.131 умела сохранять незаписанный план после refresh. Проверка старой 0.3.131 подтвердила сохранение открытого состояния при переключении, а форма проверена отправкой захваченного старого payload. Старые hashed assets обслуживались при соответствующем переходе; union ограничен текущим и одним предыдущим выпуском.

## Исправленный инцидент упаковки ключа

В первых пяти image artifacts этой работы был опубликован compiler key из Next manifests. Репозиторий публичный. Эти artifacts удалены; отсутствие внешнего чтения не доказано, история скачиваний недоступна. Активный runtime AES-256 key заменён, стал приватным host-only файлом mode 600 и больше не передаётся в CI. Прежнее значение используется только как compiler ID salt для сохранения всех 10 уже существующих action IDs.

Новая сборка в том же build layer очищает оба Node manifests, проверяет runtime reference в edge manifest, удаляет private caches и потоково проверяет всё build output на остатки salt. Проверка нового образа показывает пустой manifest key, отсутствие runtime key в image environment и совпадение runtime env с новым приватным host key. [Инцидент и удалённые ID](action-key-recovery.json), [readback](action-manifest-137.json). Текущие actions — unbound module-level; будущие closure/bound actions требуют отдельной проверки совместимости, как закреплено в каноне.

При браузерной проверке также был выведен одноразовый QA token. Он сразу отозван и заменён; итоговая собственная QA-сессия удалена после проверок. Пользовательские сессии ради этой проверки не отзывались. Токены и приватные env в Git/evidence не сохраняются. Во время mobile-проверки выбранные 11 колонок действительно записались в настройки пользователя. Обнаружив это, восстановил два прежних NULL-поля только после точной сверки известной тестовой комбинации и compare-and-set. Проверка после восстановления совпала с исходным состоянием, удалена ровно одна QA-сессия, чужие сессии не менялись. [Результат](qa-session-cleanup.json).
