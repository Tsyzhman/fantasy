# Синхронизация вероятных стартовых составов

Команда загружает вероятные составы из трёх публичных источников:

- Premier League: `https://www.fantasyfootballscout.co.uk/team-news/`
- Serie A: `https://www.gazzetta.it/Calcio/prob_form/`
- Bundesliga: `https://www.ligainsider.de/`

Для Бундеслиги главная страница используется как каталог актуальных 18 клубов.
После этого каждая клубная страница вида `/<club>/<id>/` загружается отдельно.
Список URL не захардкожен, поэтому повышение и вылет команд не требуют правки
скрипта.

По умолчанию выполняется только проверка без записи в БД:

```bash
npm run starters:sync-probable
```

После просмотра отчёта применить полностью распознанные составы:

```bash
npm run starters:sync-probable -- --apply
```

Ограничить источник или явно выбрать сезон:

```bash
npm run starters:sync-probable -- --source epl --season 2026/2027 --apply
npm run starters:sync-probable -- --source serie-a --json
npm run starters:sync-probable -- --source bundesliga --json
```

## Защита данных

- Источник принимается только при наличии ровно 20 команд для EPL/Serie A или
  18 команд для Bundesliga и 11 уникальных игроков у каждой команды. Изменение
  разметки или неполный ответ останавливают обработку всего источника.
- Команда в БД меняется только при однозначном сопоставлении всех 11 игроков с
  её активным FotMob-ростером; первый игрок должен быть вратарём, а во всей XI
  должен быть ровно один вратарь. Нераспознанная команда или игрок пропускаются
  и выводятся в отчёте.
- Для EPL сначала используется точный официальный player/team code из уже
  сохранённой карты FPL ↔ FotMob. Имена применяются только как резервный путь.
  Для Gazzetta сопоставление ограничено одной командой и использует имя плюс
  номер футболки, когда он доступен. Для LigaInsider полное имя восстанавливается
  из URL профиля игрока; скрытые альтернативы на позиции не входят в XI.
- Каждая команда обновляется в отдельной транзакции под тем же advisory lock,
  который используют ручное редактирование и импорт фактического состава.
- Повторный запуск с теми же 11 игроками не пишет в БД и не инвалидирует кэш
  расчёта составов.
- Исходный HTML не сохраняется. Каждый ответ ограничен 2 MiB, источники и 18
  страниц LigaInsider обрабатываются последовательно. Между клубными запросами
  выдерживается пауза 500 мс; в памяти находится HTML только одной страницы.

В `LeagueSeasonTeam.metadata.probableLineup` сохраняется только компактное
происхождение применённого состава: источник, время, схема, соперник, имена,
номера/коды игроков и SHA-256 fingerprint.

## Коды завершения

- `0`: все выбранные источники обработаны, пропусков и ошибок нет;
- `1`: источник или транзакция завершились ошибкой;
- `2`: страницы корректны, но одна или несколько команд/игроков не удалось
  однозначно связать с активным ростером.

Все аргументы доступны через:

```bash
npm run starters:sync-probable -- --help
```
