# Можно ли обыграть букмекера на данных Fantasy Scout?

Дата: 7 сентября 2026. Исследование WI-002. Production прочитан через SSH `deploy`; приложение и БД не изменялись.

Продолжение по просьбе пользователя: [расширенный тест весов, календаря и погоды, WI-003](BETTING_FEATURE_RESEARCH_2026-09-07.md). Этот документ сохраняет результаты первого, базового прохода.

## Ответ

**Устойчивый ROI 20–30% на оборот ставок имеющимися данными не подтверждён. Проверенные модели преимущества перед букмекером не показали.** Данных достаточно для исследовательского прототипа, но недостаточно для обещания доходности. Это проверка нескольких разумных базовых подходов, а не доказательство невозможности любой прибыльной стратегии.

ROI здесь — чистая прибыль / сумма всех ставок. Это не доходность первоначального банка за год. При коэффициенте 2.00 математическое ожидание ROI 20% требует истинной вероятности выигрыша 60%, а 30% — 65%. Формула для одной ставки: `EV = p × odds − 1`.

## Проблемы качества и времени

1. У **2 626 завершённых матчей** отсутствует хотя бы одно поле итогового счёта в `matches`, включая все **380 матчей АПЛ 2025/26**. В командной статистике счёт АПЛ есть, но в **36 случаях** он расходится с внешним архивом. Например, Fulham — Manchester United, 24.08.2025: резервные командные голы дают 2:0, архив — 1:1; в событиях присутствует автогол. Причина каждого расхождения отдельно не расследована. В эксперименте для всех сопоставленных матчей результат одинаково взят из внешнего архива, включая предыдущие матчи при построении формы. Production не исправлялся.
2. **12 540 из 13 781 матчей** добавлены в нашу БД уже после игры. Многие прошлые fantasy-прогнозы рассчитаны в августе 2026. Их нельзя выдавать за прогнозы, фактически выпущенные перед историческим матчем.
3. **История Фонбета перезаписывается:** уникальность `(match_id, provider)` и `upsert` сохраняют последний снимок. Нет полного журнала изменения коэффициентов, принятия ставок, доступного лимита и сравнения нашей цены с закрытием рынка.
4. Из 496 снимков Фонбета 331 относится к завершённым матчам. До начала сняты **122**, более чем за 5 минут — **121**, более чем за час — **27**. У 209 timestamp совпадает с началом либо позже. Большинство опозданий меньше минуты; только три больше минуты. Это не означает, что все 209 содержат информацию live, но строгий предматчевый тест не может считать их заведомо доступными заранее.
5. Дублей по проверенным ключам матчей, Фонбета и fingerprints ударов нет. Найдена одна строка командной статистики с командой, не совпадающей с хозяевами или гостями; исследовательское соединение берёт только точные home/away team IDs.
6. xG игроков заполнен в 150 769 строках из 473 577. Нулевое значение и отсутствие значения не тождественны; часть строк относится к запасным и игрокам без ударов. Для player props требуется отдельная проверка этих семантик.
7. Встречаются странные метки сезона: некоторые кубковые матчи 2025/26 помечены 2026/27. Разбиение теста сделано по дате игры, а не по строке сезона.

## Как выполнена проверка

Источник коэффициентов и результатов — [Football-Data](https://football-data.co.uk/downloadm.php), файлы `mmz4281/2526/{E0,E1,D1,I1,SP1,F1,N1,P1,B1,T1}.csv`. Использованы **закрывающие коэффициенты Bet365**, не лучшие задним числом цены разных букмекеров. [Описание колонок](https://football-data.co.uk/notes.txt) отличает closing-поля с `C` от более раннего снимка.

Из 3 533 архивных матчей сопоставлены **3 532**, один исключён из-за отсутствия однозначного совпадения даты и команд. Матчинг использует лигу, точную дату и названия обеих команд; итог не участвует в выборе соответствия. Слабые совпадения названий проверены вручную. Все 36 расхождений результатов сохранены, а не исключены из теста по исходу.

Признаки: последние до десяти матчей каждой команды в той же лиге, минимально пять матчей на команду; средние забитые/пропущенные голы, xG за/против, удары и удары в створ за/против, отдых. Средние с небольшим фиксированным сглаживанием. Все матчи одного UTC-дня обрабатываются до обновления истории: статистика текущего матча и игр того же дня в признаки не попадает.

Сравнены четыре варианта: фиксированный Poisson по прошлым xG; логистическая регрессия по форме/голам/xG/ударам; смесь 80% рыночной вероятности без маржи и 20% xG-модели; рыночная вероятность без маржи. Последняя — ориентир качества и отдельная проверка расхождений Bet365 с усреднённым рынком. Снятие маржи применяется только для оценки вероятностей; выплаты всегда считают по реальным коэффициентам с маржой.

Хронологический протокол:

- Обучение до 01.11.2025: **466 матчей** после прогрева истории и проверки коэффициентов.
- Выбор модели/порога на ноябре–декабре 2025: **746 матчей**.
- Переобучение регрессии на всём периоде до января, затем независимый по времени тест января–мая 2026: **1 837 матчей**. Параметры внутри теста не переобучаются; предыдущая форма обновляется по ходу календаря.
- На рынок четыре модели × четыре порога модельного EV: 0%, 5%, 10%, 20%. Правило допуска: положительный validation ROI минимум на 50 ставках. **Ни один вариант не прошёл это правило ни для исходов, ни для тоталов.** Поэтому исследование не выбрало стратегию для применения. Ниже показаны диагностические результаты заранее заданного порога 5% для прозрачности.
- Фиксированная ставка 1 единица; коэффициенты 1.20–6.00; максимум один выбранный исход на матч в каждом отдельно проверяемом рынке. Результаты рынков не складываются в якобы независимый портфель.

## Полученный ROI

| Стратегия при модельном EV ≥5% | Ставок | ROI | 95% интервал, блоки по неделям |
|---|---:|---:|---:|
| Исход 1X2, прошлый xG / Poisson | 1 388 | **−13,63%** | −25,27…−1,87% |
| Исход 1X2, форма + голы + xG + удары | 1 350 | **−7,48%** | −13,82…−0,73% |
| Исход 1X2, 80% рынок + 20% xG | 307 | **−0,20%** | −27,21…+27,53% |
| Тотал 2.5, прошлый xG / Poisson | 918 | **−6,13%** | −14,44…+2,06% |
| Тотал 2.5, форма + голы + xG + удары | 986 | **−4,89%** | −11,31…+2,15% |
| Тотал 2.5, 80% рынок + 20% xG | 100 | **−16,59%** | −43,12…+10,69% |
| Фонбет, индивидуальные тоталы 1.5, прошлый xG | 71 | **+0,28%** | −48,75…+55,14% |

Фонбет проверен отдельно за июль–сентябрь 2026: снимок более чем за пять минут до старта; история обеих команд должна предшествовать дню снимка. Из 121 такого матча для 82 хватает истории, в 71 найдено модельное EV ≥5%. Прибыль всего **0,20 единицы**, максимальная просадка **17,92 единицы**. Снижение доступного коэффициента на 2% превращает ROI в **−1,72%**. Порог EV 10% даёт +2,08% на 60 ставках, а 20% — −23,07% на 43: это диагностические срезы, не независимые подтверждения.

Интервалы получены 10 000 повторных выборок недельных блоков с фиксированным seed. У большого теста только 20 недель, у Фонбета семь: интервалы приблизительные, не учитывают все виды зависимости и неопределённость выбора модели. Для Фонбета доказательная сила особенно мала. Процент выигрышных bootstrap-выборок не трактуется как вероятность будущей прибыли.

Средняя букмекерская надбавка `sum(1/odds) − 1` в тесте: **6,60% для 1X2**, **5,35% для тоталов**. Это показатель маржи котировок, а не точное ожидаемое отрицательное ROI любой стратегии.

Рынок точнее проверенных моделей и по качеству вероятностей: log loss исходов **0,9899** у усреднённого рынка против **1,0248** у регрессии и **1,0379** у Poisson; меньше лучше. Для тоталов соответственно **0,6723 / 0,6831 / 0,6819**. В этом тесте добавление нашей простой xG-модели к рынку также не улучшило общий log loss.

Интерактивный график интервалов: `specs/work/evidence/WI-002/roi_intervals.html`.

## Что доказано, а что пока нет

Доказано в рамках эксперимента: обычные прошлые xG, результаты и удары сами по себе не дали проверенным моделям преимущества над выбранными закрывающими ценами. Модельное EV 20–30% не означает реальную доходность 20–30%: ошибки вероятностей концентрируются именно в ставках, которые модель считает наиболее выгодными.

Не доказано: невозможность выигрывать вообще, доходность более сильных моделей, более ранних линий, конкретных ошибок Фонбета или player props. В тесте не использованы полноценные модели составов/минут, травм, игроков, пространственных профилей ударов, движения цены, карточек и угловых. Часть этих рынков имеет статистическую основу в нашей БД, но сопоставимого архива цен здесь нет.

Это **ретроспективная реконструкция**, а не журнал реальных предматчевых прогнозов: текущие версии прошлой публичной статистики считаются доступными после дня соответствующей игры. Версии xG и исправления поставщика на тот момент не сохранены. Нельзя утверждать, что наш production реально располагал такими признаками тогда. Close из внешнего архива тоже не доказывает принятие нужной суммы конкретным букмекером. Налоги, ограничения счетов и индивидуальные лимиты не моделировались; тест и до них не показывает устойчивого плюса.

Первые диагностические расчёты были пересчитаны после исправления соединений и единообразного источника счёта. После просмотра теста качество данных проверялось, но модели/пороги не менялись ради роста ROI. Всё исследование остаётся exploratory: этот период уже изучен, поэтому следующая гипотеза должна получить новый нетронутый период или forward-test.

## Где есть смысл искать преимущество дальше

1. **Архивировать наблюдения коэффициентов без перезаписи.** Нужны bookmaker, event/market/selection, линия, odds, timestamp получения, начало игры, prematch/live, статус доступности и по возможности лимит. Сохранять момент собственного прогноза и входные данные.
2. **Проверять цену относительно рынка.** Сравнивать Фонбет с одновременными котировками нескольких независимых букмекеров, снимать маржу и проверять, сохраняется ли преимущество к закрытию. Это отдельная гипотеза; текущая БД её не позволяет полноценно испытать.
3. **Изучить один рынок игроков.** Например, удары/удары в створ при подтверждённом старте: у нас есть индивидуальная интенсивность, минуты и профиль соперника. Но нужны исторические линии, составы с временем публикации, правила расчёта ставки и корректные нули. Это направление исследования, не доказанная прибыльная ниша.
4. **Исправить договорённости о счёте, автоголах, пропусках и сезонах.** Сверять исходы с независимым источником. Не запускать ставочный контур на неявных fallback.
5. **Фиксировать модель и оценивать новые сигналы вперёд.** Первое требование — положительное ожидание после реально доступной цены и расходов, стабильность по периодам и улучшение вероятностей/цены. Тысячи ставок дают больше информации, но не являются автоматическим сертификатом: при odds около 2.0 и независимых ставках 1 000 наблюдений дают примерно ±6,2 процентного пункта для 95% интервала ROI возле нуля; 10 000 — ±2,0 п.п. Зависимость и большие odds увеличивают необходимую выборку.

**Бизнес-план с постоянным ROI 20–30% на основании этой БД сейчас необоснован.** Возможность искать редкие ошибки цен есть; существование устойчивого преимущества ещё предстоит доказать.

## Внешние основания

- [Kaunitz, Zhong, Kreiner: Beating the bookies with their own numbers](https://arxiv.org/abs/1710.02824): исследование выявляло ошибки котировок относительно рынка и включает реальные ставки; также описывает ограничения успешных клиентов. Это пример возможности преимущества, не оценка нашего ROI.
- [Dmochowski, PLOS ONE](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0287601): прибыльная ставка зависит от вероятности относительно цены, а не только от способности угадать победителя.
- [Chronological validation, scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html): мотивация разделять прошлое и будущее. Здесь реализованы фиксированные календарные окна и лаг признаков, не случайный train/test split.
- По запросу проекта изучены обсуждения на Reddit и Stack Overflow о leakage, выборе порога на тесте и недоступных задним числом ценах; численные выводы отчёта на свидетельствах форумов не основаны.

## Воспроизводимость и ресурсы

`specs/work/evidence/WI-002/inputs.zip` содержит один сжатый экземпляр спортивных входных данных и внешних CSV; SHA-256 каждого файла указан в `input_manifest.json`. Персональные данные, секреты и пользовательские таблицы не выгружались. SQL работал в read-only транзакциях, с ограничением запроса 30 секунд и `work_mem=8MB`; модели рассчитаны локально.

Восстановить входные данные из корня репозитория:

```powershell
Expand-Archive -LiteralPath specs/work/evidence/WI-002/inputs.zip -DestinationPath .tmp/betting-research-20260907 -Force
python scripts/research/betting_backtest.py
python scripts/research/betting_evaluate.py
python scripts/research/betting_report.py
```

Использованы Python 3.14, NumPy, pandas, SciPy, scikit-learn, Plotly. Точные версии сохранены в `verification.json`. Для новой выгрузки — `python scripts/research/betting_audit.py`; она обращается к живой БД, поэтому не воспроизводит в точности прежний снимок.

Проверены независимость признаков от изменения результатов/статистики того же дня и будущего, формула выплаты, отсутствие повторной ставки на один матч внутри стратегии и даты holdout. Сохранены полный grid, конкретные выбранные ставки и coverage. Production не перезапускался, контейнеры для тестов не создавались. Контроль памяти и состояния — `resources.txt`.

Очистку локальной `.tmp/betting-research-20260907` и Python-кэша автоматическая проверка отклонила с причиной `blocked by policy`, без уточнения. Около 20 MB временных входов, pickle и логов остаются наряду с проверенным сжатым архивом 1,69 MB. В evidence также остались три идентичных набора ставок для lead>0 и lead>5; они представляют одинаковые ставки при двух условиях, а не дополнительные наблюдения. При воспроизведении код сохраняет только lead>5 и lead>60. Исследовательских процессов в фоне нет.

Было: предположение о возможном высоком ROI и несопоставленные источники данных. Стало: проверяемый аудит, воспроизводимые симуляции, зафиксированные ограничения и отрицательный результат для проверенных подходов. Код продукта, UI и production-данные не изменены.
